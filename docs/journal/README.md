# Build Journal

Add one dated Markdown entry for each substantial build session, test day, or meaningful setback. Use `template.md` as a starting point; name entries `YYYY-MM-DD-short-topic.md`.

Prioritize contemporaneous observations over polished storytelling. Record what changed, what was expected, what actually happened, what was difficult, and what should happen next. Link to related decision records, experiments, design files, firmware changes, and media where possible.

These entries are the chronological record of the build. Later thesis and portfolio writing should cite or link back to them rather than quietly rewriting history.
